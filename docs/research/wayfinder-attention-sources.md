# Official platform metrics for electoral attention

**Investigation date:** 2026-10-13.  
**Research ticket:** [Issue #4 — Verificar fontes permitidas e janelas comparáveis para atenção eleitoral](https://github.com/dargmiguel/dinheiro-compra-votos/issues/4)  
**Question:** Which official YouTube API, Meta and Google Trends measures can be linked to candidates/campaigns and retrieved historically for a comparable 2026 electoral window, with definitions, grain, limits, authorization, terms and retention?

This report distinguishes public data from account-authorized insights. “Candidate/campaign link” means the official API exposes a channel/Page/video/topic or search term that can be matched externally; none of these APIs documents a canonical election-candidate identifier or performs that linkage for the researcher. Candidate-to-account/content attribution therefore remains an independently documented entity-matching step, not a source-provided fact. No undocumented endpoint or access workaround is proposed.

## Summary of documented availability

| Source | Publicly obtainable, candidate-linkable data | Historical measure for a comparable election window | Main blocker / caveat |
|---|---|---|---|
| YouTube Data API | Public video metadata and current `viewCount`, `likeCount`, `commentCount`; public channel metadata/statistics. Link only to a selected public video/channel ID. | The API documents current statistics, not historical time-series retrieval. Historical snapshots require lawful prior capture; do not treat current counters as window-specific values. | Search is quota-limited; no official candidate classification. Non-authorized API data retention is capped at 30 days and refresh is required. |
| YouTube Analytics API / Reporting API | Channel-owner analytics (e.g. views, watch time, engagement, subscriber gain/loss) at dates/video/channel dimensions, subject to report compatibility. | Date-range reports support retrospective queries, but docs do not establish universal earliest dates or coverage for arbitrary channels. A campaign owner must authorize the relevant channel/content owner. | Not public third-party data: OAuth authorization is required; authorized data is not to be disclosed beyond authorizing user/approved agents, and YouTube policy restricts aggregation/derived metrics. |

## YouTube

### Public YouTube Data API — current counters and metadata

The Data API `videos.list` resource exposes a video's `snippet` (including `publishedAt`, `channelId`, title), and `statistics` fields including `viewCount`, `likeCount`, and `commentCount`; the API presents a video resource, not a candidate/campaign entity. Channel-level resource fields include channel statistics; all fields should be interpreted according to their documented availability and not presumed to exist for every video/channel. ([Videos resource](https://developers.google.com/youtube/v3/docs/videos); [Channels resource](https://developers.google.com/youtube/v3/docs/channels))

These values are **current snapshot statistics** in the Data API; the public reference does not document a date parameter for retrieving past values. A public video published in the desired period can be identified by its published date, but its current total is not a historical count “as of” any past day. Public video search can find content, but does not prove that a video belongs to the candidate/campaign.

* **Grain:** one video or channel resource per ID; statistics are current cumulative counters, not a date-series report.
* **Authentication:** API project credentials. Data API calls for public data do not require end-user OAuth; private/account-specific actions do. ([YouTube API Services Developer Policies, III.D.2](https://developers.google.com/youtube/terms/developer-policies))
* **Quota:** projects default to 10,000 units/day shared among most methods; `search.list` has a separate 100 calls/day default bucket and costs one unit per call; `videos.list` and `channels.list` cost one unit. Every request costs at least one unit; each pagination request is charged. Quotas reset midnight Pacific Time. ([Quota calculator](https://developers.google.com/youtube/v3/determine_quota_cost))
* **Terms/retention:** Non-authorized API data may be temporarily stored for at most 30 calendar days, then must be deleted or refreshed. Authorized statistics can be retained as necessary, but authorization and resource availability must be rechecked at least every 30 days. Data subject to an account deletion request must be deleted as soon as possible, within seven days. Do not scrape YouTube applications. ([YouTube API Services Developer Policies, III.E.4, III.F.6](https://developers.google.com/youtube/terms/developer-policies))

### YouTube Analytics and Reporting — authorized historical account insights

The YouTube Analytics API offers owner-authorized metrics including `views` (report-specific definition), `engagedViews` (views past the first frame or explicit play), `estimatedMinutesWatched`, `averageViewDuration`, `averageViewPercentage`, `likes`, `comments`, `shares`, `subscribersGained`, and `subscribersLost`. Definitions are metric-specific; e.g. `subscribersGained` in a video-filtered report counts subscriptions from the video's watch page, whereas a channel report includes subscriptions from multiple surfaces. ([Metric definitions](https://developers.google.com/youtube/analytics/metrics))

The API supports report queries with start/end dates and dimensions such as date/video, subject to supported dimension/metric combinations; reports use Pacific Time. Documentation specifies a query range but **does not state a universal earliest date or promise that every metric is available for every channel/video/date**, so prior-year coverage must be confirmed per authorized property/report. The Reporting API is also owner-authorized and produces bulk reports; it does not create public third-party analytics access. ([Analytics `reports.query`](https://developers.google.com/youtube/analytics/reference); [dimensions](https://developers.google.com/youtube/analytics/dimensions); [Reporting API](https://developers.google.com/youtube/reporting))

* **Grain:** daily date and video/channel reporting, depending on selected report dimensions and API metric-dimension compatibility; some metrics are channel-wide, some can be filtered by video. Do not assume every combination can be requested.
* **Authentication:** OAuth; all Analytics and Reporting API actions require authorization. Read-only analytics scopes include `yt-analytics.readonly` and (if monetary measures are used) `yt-analytics-monetary.readonly`. ([Analytics reference/auth](https://developers.google.com/youtube/analytics/reference); [Developer Policies](https://developers.google.com/youtube/terms/developer-policies))
* **Authorization/privacy:** authorized analytics is accessible only to authorizing user or agents expressly approved by that user. The owner’s cooperation is therefore required for candidate/campaign analytics; public visibility of videos does not confer access to channel insights. ([Developer Policies, III.E.3](https://developers.google.com/youtube/terms/developer-policies))
* **Retention/terms:** authorized Analytics/Reporting data may be retained as necessary for the user-consented purpose, but authorization must be rechecked every 30 days. Revoke-token consent requires deletion within seven days; deletion after permission revocation is within 30 days as specified by policy. YouTube policy prohibits creating new/derived metrics from API data and prohibits aggregation across different content owners; this materially limits use of API-returned account metrics in cross-candidate scores or pooled indices. ([Developer Policies, III.E.2, III.E.4](https://developers.google.com/youtube/terms/developer-policies))
* **Access blocker:** No general public historical YouTube Analytics endpoint exists in these docs. Coverage for candidates who do not authorize their channels remains unavailable through these APIs.

## Meta (Facebook Pages / Graph API)

### Public Page-level data

Meta’s Page reference identifies `fan_count` (for New Page Experience, the field returns `followers_count`) and `followers_count`; its definition of `fan_count` is users who like the Page (or followers for New Page Experience), and global Pages may aggregate across the brand. This is Page-level profile data, not candidate-specific reach or support. Published, unrestricted Pages can expose public data only with app approval for Page Public Content Access (PPCA) or Page Public Metadata Access (PPMA); available public fields vary by feature. Public access is distinct from Page-owned data access. ([Page reference](https://developers.facebook.com/docs/graph-api/reference/page/); [Pages API overview: features and permissions](https://developers.facebook.com/documentation/pages-api/overview))

Public data access therefore does not yield the private Page Insights metrics listed below. Documentation does not establish that all candidate Pages are queryable, that Page search yields complete electoral coverage, or a historical time series for follower counts. No public historical API is documented here for reconstructing past Page follower values.

### Page Insights — Page-authorized only

The Page Insights endpoint provides metrics for Facebook Pages and their posts. The endpoint requires a Page access token requested by a person able to perform the `ANALYZE` task, and the `read_insights` and `pages_read_engagement` permissions. Meta says Page Insights data is available only on Pages with at least 100 likes; most metrics update once per 24 hours; only the last two years of insight data are available; and only 90 days may be viewed at once using `since`/`until`. Demographics are returned only where data exists for at least 100 people. Some video metrics are accurate only for the Page video-post creator; interactions on Reels are excluded. ([Page Insights reference](https://developers.facebook.com/docs/graph-api/reference/v26.0/insights))

The endpoint describes insight metrics at Page or Page-post level. Metric names are separately defined in Meta's reference; examples include Page impressions and post reach/engagement metrics, with `_unique` indicating approximate unique-user counts. Period options vary by metric; use only metrics whose specific definition and supported period in the reference match the intended measure. The 90-day limit is an extraction window, not a metric grain guarantee. (Same [Page Insights reference](https://developers.facebook.com/docs/graph-api/reference/v26.0/insights))

* **Historical fit:** As documented on the 2026-10-13 reference, the two-year rolling limit could include a 2026 election window if fetched while within that limit and the Page qualifies, but each request can retrieve at most 90 days. A later extraction may lose older history. The 100-like threshold may omit smaller Pages.
* **Public vs private:** Public Page profile/content access via PPCA/PPMA does not waive the Page Insights authorization requirements. Analytics requires actual Page access and `ANALYZE` task; there is no official general endpoint that grants candidate Page Insights to an unaffiliated researcher solely because the Page is public.
* **Rate limits:** All requests are rate-limited. Application-token requests have a rolling-hour formula of `200 × unique daily active users` (or weekly/monthly active users where applicable); Page/system-user tokens use Business Use Case limits, and Page tokens can be throttled. Exact live limits vary by app/token and usage; inspect rate-limit response headers/dashboard. ([Graph API rate limits](https://developers.facebook.com/docs/graph-api/overview/rate-limiting/))
* **Terms/retention:** Meta Platform Terms require deletion of Platform Data when no longer needed for a legitimate permitted purpose and promptly upon user/Meta request or other listed events; they do not provide a universal number-of-days retention allowance. Keep only data consistent with documented permitted purposes, applicable terms/law, and user permissions; deletions/consent controls apply. ([Meta Platform Terms, §§3–4](https://developers.facebook.com/terms/))
* **Access blocker:** PPCA/PPMA requires app feature approval through App Review; Insights further requires Page owner/authorized task access. The public docs cannot prove any particular app will be approved or any Page owner will cooperate. ([Pages API overview](https://developers.facebook.com/documentation/pages-api/overview); [Insights reference](https://developers.facebook.com/docs/graph-api/reference/v26.0/insights))

## Google Trends

### API alpha search-interest data

Google announced a Google Trends API alpha on 2025-07-24. It provides consistently scaled search-interest series, with a rolling 1,800-day (~five-year) window, data up to two days before the request, daily/weekly/monthly/yearly aggregation, and geography including region/sub-region. Unlike the Trends website’s request-relative 0–100 normalization, the API’s scale is consistent across requests to make multiple requests comparable, but still represents **search interest**, not absolute search counts. Google’s published material says access is limited to alpha testers selected after an application; the accessible official page continues to invite applications. ([Announcement](https://developers.google.com/search/blog/2025/07/trends-api); [API alpha page](https://developers.google.com/search/apis/trends))

* **Metric definition:** Google Trends is a largely unfiltered, anonymized, categorized and aggregated sample of actual Google searches; values are normalized against total searches for the queried geography/time and scaled. Low-volume terms can show `0`; privacy noise can affect small-volume searches; repeated searches from a user are deduplicated. It is not polling and does not indicate candidate preference, popularity, or electoral likelihood. ([Google Trends FAQ](https://support.google.com/trends/answer/4365533); [API announcement](https://developers.google.com/search/blog/2025/07/trends-api))
* **Grain:** requested search term/topic × time aggregation × region/sub-region as supported; no candidate ID, unique searchers, or absolute volume is documented. Exact metric name, endpoint schema, query combination limits and full API reference are not published on the alpha landing page.
* **Historical fit:** The rolling five-year history should cover a comparable 2026 election window if it falls within 1,800 days of retrieval; data is only stated to reach two days before request. This is a documented product range, not a guarantee for every query/geo, nor proof that API alpha access is available to this project.
* **Access/limits/auth:** Alpha access is limited to selected applicants. Published sources do not specify endpoint quotas, per-request term/geo limits, authentication scopes, or broad public launch timing; these remain unknown rather than inferred. The Trends website is public, but it is not an API substitute with the API’s stable scaling and programmatic access.
* **Terms/retention:** The public alpha pages cited here do not specify API data retention terms, permitted research-use restrictions beyond the general Google developer site terms, or retention duration. That does not imply unrestricted retention; applicable terms must be obtained with access before use. ([API alpha page](https://developers.google.com/search/apis/trends); [Google Developers Site Policies](https://developers.google.com/site-policies))

## Coverage and comparability limitations

1. Public view/follower/search-interest counts are not equivalent measures: video totals, page followers, Page Insights and normalized search interest have different populations, definitions, grains and authorization states. They must remain separately identified rather than combined as if they measured a common quantity.
2. API account/content identity linkage is not supplied by any of these services. A reproducible campaign match requires an external documented account/content crosswalk; ambiguous names and fan/unofficial pages are unresolved by these platform endpoints.
3. The Data API returns a current YouTube counter, not historic snapshots; Meta's Page Insights history is limited to two years and requires Page access; Google Trends API offers rolling five-year history but remains alpha and limited access. Historical values therefore cannot be assumed uniformly available across platforms or candidates.
4. No candidate-level completeness, API approval, owner consent, history for a specific channel/Page/query, or quota increase was tested or assumed in this research.
